# Security notes

## Current state

This repository contains a substantial but incomplete Supabase backend: 102 forward-only migrations, 87 pgTAP files, 28 Edge Function folders, fictional seed fixtures, and static security lint. The user reports the full local Phase 8 sequence passed, including reset/database/function tests and checks, types, contract export, and static checks; this is user-reported, not assistant-run. The Phase 8 source implementation is closed at the local scope. The backend is **not ready for production deployment or real student data**: production product/security decisions, hosted configuration, n8n runtime/deployment validation, DNS/egress protections, and an independent security review remain outstanding. Static-source checks do not replace a deployment security review. The `private` schema is not Data-API exposed by config.

## Assumptions and limitations

- Every current `admin-*` Edge Function declares JWT auth, the `admin` role, and the shared AAL2 gate. `npm run security:admin-aal2` statically checks this shape across the folders and its negative-case tests run in CI. This source lint does not prove the shared handler or every downstream database RPC enforces the expected JWT claims; pgTAP/runtime tests remain required.
- `npm run db:reset` is guarded by `APP_ENV=local|demo`, with a production/missing/unknown value rejected before invoking the Supabase CLI. After successful reset it automatically executes the fictional demo-state assertions. This protects the repository's npm reset path only; do not bypass it with a direct destructive CLI command or point this checkout at a hosted project.
- `npm run test:secret-scan` exercises representative known-key patterns and placeholders; `npm run secret:scan` source-scans the workspace for a small set of recognized private-key, Supabase, AWS, GitHub, Google, OpenAI, Anthropic, Groq, OpenRouter, Hugging Face, and Stripe token patterns and redacts matched values in its output. It excludes `.env.example`; `npm run test:env-example` covers missing keys/references, unsafe operation defaults, and sensitive-placeholder rejection; `npm run check:env-example` checks the actual template, requiring local/mock/off defaults and loopback SUPABASE_URL. Neither check detects every credential format, secret-manager leak, or runtime secret exposure; review files and logs manually too.

- Reveal document/video signed URLs are issued only after combined ownership-prefix and exact-key validation helpers; data-export signing validates the owner-scoped UUID path and removes the new object if link creation or audit logging fails. Link TTLs are fixed at 600 seconds and Storage errors are suppressed. Fake-bucket and SDK-level request tests cover these helper gates; the user reports the full local Deno suite passed, but individual assertion output was not provided for independent review. The submission's `video_seconds` remains client-reported and untrusted. The local synthetic Gemini audit now independently parses bounded MP4/MOV/WebM container duration metadata and fails closed for missing, malformed, unsupported, or over-limit media. Container metadata is not a full decode/playability check; production processing still needs reviewed media tooling and provider/privacy controls.
- Free-tier LLM providers may retain or train on prompts. Direct integrations for job-description extraction, assignment wording, and a constrained audit path exist only for local synthetic testing; bounded owner-scoped video may be sent inline to Gemini. They require `APP_ENV=local`, `LLM_ALLOW_SYNTHETIC_DIRECT=true`, and a `.test` caller where wired; use only fictional, redacted fixtures. Direct matching/profile LLM agents remain incomplete. All n8n adapter paths are local-synthetic-only and inactive by default; `AGENT_MODE=n8n` is configurable only with `APP_ENV=local`, `N8N_ALLOW_SYNTHETIC=true`, and validated audit/assign/match/profile endpoints (separate from the direct-LLM opt-in). its dispatch helper limits payloads to 512 KB and rejects obvious private callback destinations, while Compose caps webhook payloads at 1 MB. Before ACK, the workflow validates the callback URL against an exact operator-configured hostname allowlist (`N8N_CALLBACK_ALLOWED_HOSTS`) and the provider URL as HTTPS on a chat-completions path against its exact allowlist (`N8N_LLM_ALLOWED_HOSTS`); both reject credentials, query/fragment, nonstandard ports, literal IP/local/reserved test hosts (callback path must be exactly `/functions/v1/agent-callback`). Hostname DNS resolution is not pinned/checked in the Edge Function or workflow, so deployment egress/DNS controls must prevent public names resolving to private networks. The imported workflow accesses host-provided webhook/callback/provider secrets from n8n Code nodes, so only trusted workflow editors may access the n8n console, TLS/reverse-proxy access must be secured, and the workflow must be reviewed before activation. It does not replace a full provider-retention review. The provider path has a configurable global daily cap (`LLM_DAILY_CAP_PER_PROVIDER`, default 1000), but provider billing, retention, and training settings must be reviewed separately.
- `roster-import` and `register-student` use `ID_HASH_PEPPER` to HMAC-normalize roster student IDs. Never log or persist raw IDs. `roster-import` authorizes university membership before privileged access and requires CSV paths under that university's `rosters/` prefix. Batch processing is delegated to service-role-only `public.process_roster_import`, which rechecks membership and executes the batch transactionally. The user reports the local database suite passed; these results are not independently reproduced in this workspace.
- Matching demand aggregates contain only per-university reason counts and skill slugs. A service-role-only RPC validates and replaces them under a per-job row lock, atomically clearing stale aggregates. Match rows, count-only new-match notices, and the audit event are now committed through service-only `persist_job_matches` in migration `0099`; it locks the job, share-locks active organization/membership state, and locks matched student rows while rechecking live discoverability. The user reports that local `db:test` passed after the `0086` correction; this is user-reported, not an independent database execution by the assistant.
- Rate limiting is only partially wired. HMAC callback verification and submit-application idempotency have code paths; the user reports local tests/checks pass, but production traffic behavior and rate-limit coverage remain unverified. Complete production agent processing remains unavailable.
- GitHub OAuth tokens for `profile-sync` use service-role-only Vault wrapper RPCs. The local OAuth callback uses one-time HMAC-hashed state bound to the student and source. Do not add real GitHub credentials or peppers to `.env.example`, docs, or fixtures.
- `audit-submission` is an internal service-role-only synthetic worker for fictional `.test` accounts. Its mock path treats `submission:<id>` strictly as a record locator, not a citation; it does not fabricate evidence, so evidence-free runs receive insufficient-evidence handling and no skill score. A direct audit path exists only for local `.test` fixtures with explicit opt-in; it reads bounded public GitHub metadata/README/source excerpts, student-owned text documents, and a validated owner-scoped video of at most 14 MB. Video bytes are sent inline only to the Gemini adapter; no arbitrary remote URL is fetched, and n8n does not receive media. Text evidence is scrubbed, but video itself cannot be reliably anonymized; never use real-person media. The worker does not execute code/tests or analyze live sites. `agent-callback` verifies a timestamped HMAC, validates typed evidence locators, commits normalized frozen `EvidenceItem` objects only from the manifest, and persists only a generic prompt-injection flag. This remains a partial, local synthetic demo pipeline; the n8n workflow has not been imported or run, and full production proof-audit evidence collection is incomplete.
- Migration `0047` adds a retention path listing RPC and an internal `retention-cleanup` Edge Function. Migration `0050` extends the same worker to remove data-export JSON older than 30 days. Migration `0051` applies the same exact-path validation in SQL for video listing and reference cleanup. The worker deletes only through the Storage API, confirms each returned removed object name, and clears video references only for confirmed deletions. The scheduled call is dormant until a Vault URL and dedicated cleanup secret are configured. The user reports the local suites passed; scheduled hosted execution and cleanup-secret provisioning remain unverified. Never test destructive retention behavior against a remote project without an approved staging plan.
- No ID-card images should be stored.

## Manual dashboard checklist

Before any hosted use, verify auth URLs for all five hosts, TOTP enrollment and verification, SMTP and confirmation settings, password minimums, rate limits, storage size/MIME limits, project API exposure, backups, and secrets. Confirm the exposed schemas are exactly `public` and disable unused APIs. Hosted limits and configuration may differ from local `config.toml`.

## Deployment-readiness blockers

- Local test/check completion is user-reported. The assistant independently ran source/static checks, not PostgreSQL or Deno suites. Keep local outputs as the test record; do not present them as an independent audit or production certification.
- Hosted use requires an isolated staging project first, then review of auth redirect URLs for all five hosts, TOTP/MFA, SMTP/confirmation settings, password/rate limits, Storage MIME/size constraints, exposed schemas/APIs, backups/retention, and secret provisioning.
- Resolve the product/security decisions in `TODO_DECISIONS.md` with the responsible owners before real student/employer data: matching thresholds, auto-claim policy, review scoring and appeals, application bounds, confidence cutoffs, rubric versioning, privacy/anonymization limitations, and profile auto-approval scope.
- n8n remains disabled by default. Before activation, import the workflow into a non-production instance, validate a signed callback end to end using HTTPS staging URLs, review provider data-retention/training terms, and enforce DNS/egress restrictions against private-network resolution. Never paste provider, callback, service-role, or webhook secrets into chat or source control.
- Several integrations are deliberately incomplete or local/synthetic-only: production media retrieval/probing and general provider/n8n media handoff, broader direct matching/profile agents, organization/university invitations, and scheduled Vault-backed retention. Direct Gemini video analysis is limited to bounded local synthetic fixtures and is not production-ready.
- A separate independent security audit against the supplied Security.md prompt remains outstanding.
